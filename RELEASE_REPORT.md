# Результат переделки для хостинга

## Реализовано

- Камера через браузерный `getUserMedia`, локальный `<video playsInline muted>`.
  Сервер не открывает устройства и не использует MJPEG-поток.
- Выбор камеры, передняя/задняя камера, понятные ошибки доступа, HTTPS и занятого
  устройства. Камера освобождается при скрытии страницы, смене вкладки и выходе.
- Кадры до 800 px отправляются на тот же домен по `/api/scan`. Только один
  незавершённый запрос на клиенте, сервер обрабатывает один кадр одновременно.
- Изолированные авторизованные сессии, отдельный доступ администратора к журналу.
  Идентичность для записи определяется сервером, scan ID привязан к сессии и
  действует 90 секунд. Повторное подтверждение не дублирует запись.
- Фото уменьшаются до распознавания, загрузка идёт в фоне, результаты кэшируются
  по содержимому. HTTP запускается до завершения подготовки лиц. Прогресс и ошибки
  показываются в интерфейсе. База и кэш находятся на постоянном диске.
- Валидация запросов, корректные 4xx, ограничения кадра, поиск и страницы журнала.
- Единый корневой Dockerfile, локальный Compose и Compose с Caddy для HTTPS на VPS.
  `PORT`, пароли и пути настраиваются через переменные среды.

## Проверки

- 12 API-тестов пройдены на Windows: вход, лимит попыток, права, изоляция сессий,
  истечение сканирования, подмена данных, повторное подтверждение, журнал.
  Распознавание в этих тестах заменено контролируемым тестовым объектом.
- 6 тестов React пройдены: вход, HTTPS, отказ разрешения, освобождение камеры
  после позднего разрешения, сообщения ошибок, отправка кадра и подтверждение.
- `CI=true npm run build`: production-сборка успешна, без предупреждений ESLint.
- Предыдущая диагностика физической камеры Windows получала кадры 640×480 через
  CAP_ANY, MSMF и DirectShow. Новый браузерный путь проверяется отдельно.

## Границы поддержки

Это веб-приложение для современных браузеров с поддержкой камеры, а не гарантия
работы на любом старом устройстве. На публичном адресе обязательны HTTPS и
разрешение пользователя. macOS, Android и iOS физически в этой среде не проверены.

Для хостинга нужен Docker/Python и постоянный диск. Статический хостинг не выполняет
распознавание. Настройка домена, HTTPS, двух паролей и диска остаётся необходимой.
Используется один экземпляр сервера; SQLite не рассчитан на несколько реплик.

Face recognition не проверяет живость человека. Система ведёт журнал выдачи и
возврата, но не хранит отдельное состояние владения каждым ключом.

`dlib-bin` предоставляет бинарный модуль dlib, но отличается названием пакета.
`pip check` сообщает об ожидаемом имени `dlib` у face-recognition; зависимости
установлены явно. Это зафиксированное ограничение упаковки, не скрытая ошибка.

Исходная SQLite-база не мигрировалась и не изменялась. Архив исходников содержит
имеющиеся фотографии сотрудников; передавать его следует приватно. `.env`,
пароли, базы, node_modules и диагностические окружения в архив не входят.
